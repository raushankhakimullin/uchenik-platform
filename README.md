# НЕ ПРИХОЖАНИН. УЧЕНИК.

Русскоязычная школа ученичества Sons of God. Это отдельный проект для будущего `uchenik.sonsofgod.ru`; основной сайт `sonsofgod.ru` и почта не затрагиваются.

**Технологии:** Next.js, React, TypeScript, Tailwind, Supabase Auth/PostgreSQL/RLS. Данные пользователя хранятся в Supabase, а не в localStorage. Без подключённого Supabase приложение не должно изображать успешный вход или сохранение.

## Запуск разработки

1. Создайте отдельный проект Supabase. В его SQL Editor последовательно выполните `supabase/migrations/202609290001_initial.sql` и `supabase/migrations/202609290002_content.sql`. Для реального деплоя предпочтительнее вести миграции через Supabase CLI, фиксируя их в Git. Не применяйте повторно seed без проверки: вставки не рассчитаны на повторное выполнение.
2. В Supabase Auth настройте URL приложения и разрешённые redirect URLs (для локального адреса разработки и будущего HTTPS-поддомена). Включите email-подтверждение и SMTP для production; проверьте письма о регистрации и восстановлении. Если SMTP не настроен, письма могут не доставляться — не считайте сценарий подтверждённым.
3. В Replit Secrets задайте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` от **того же** проекта Supabase. Anon/publishable key по назначению доступен браузеру, но хранить его значение в Git всё равно не нужно. Никогда не добавляйте в клиент `service_role` ключ.
4. `pnpm install`; затем `pnpm --filter @workspace/uchenik-platform run dev` в управляемом workflow Replit. Для проверки: `pnpm --filter @workspace/uchenik-platform run typecheck` и `pnpm --filter @workspace/uchenik-platform run build` (при наличии переменных Supabase).
5. Зарегистрируйте реальный первый аккаунт. Администратор проекта Supabase вручную выполняет в SQL Editor: `insert into public.user_roles(user_id,role) values ('UUID_ИЗ_AUTH_USERS','администратор');`. Значение UUID сверить с `auth.users` в панели Supabase; не делайте публичную кнопку самоназначения. Обычному пользователю назначить эту роль запрещает RLS.

Миграции готовят таблицы для Telegram и будущих уведомлений, но отправка сообщений и бот **не включены**. Переход по ссылке вида `https://uchenik.sonsofgod.ru/lesson/1` ведёт на текстовый урок (после входа). Поля для видеоплатформы можно использовать после отдельной настройки CDN; пока нет загруженного видео, не показывается фиктивный плеер.

## Размещение и Beget

Тип действующего тарифа Beget пока **неизвестен**. Не загружайте Next.js в каталог обычного сайта как статическую сборку: авторизация, серверные операции и проверки доступа требуют полноценного работающего приложения.

**Вариант А — подходящий сервер Beget.** Проверьте в панели Beget или у поддержки, допускает ли ваш тариф постоянно работающий процесс Node.js и reverse proxy с HTTPS. Если да — настройте сервер с поддерживаемой версией Node.js, установите зависимости `pnpm install --frozen-lockfile`, соберите `pnpm --filter @workspace/uchenik-platform run build`, запустите `pnpm --filter @workspace/uchenik-platform run serve` под менеджером процессов и проксируйте HTTPS-запросы поддомена на порт Node. Для VPS/облака Beget можно использовать Nginx и PM2/systemd, обеспечить автоматический запуск и журналирование. До выбора тарифа не предполагается наличие VPS.

**Вариант Б — приложение размещено отдельно, DNS остаётся в Beget.** Опубликуйте Next.js на хостинге с поддержкой серверного Node.js и своим доменом. В DNS-зоне Beget измените **только запись `uchenik`**, установив требуемую хостингом CNAME или A-запись, затем подтвердите поддомен и HTTPS у хостинга. Если запись уже существует, проверьте её до замены. Не меняйте A/AAAA/CNAME/MX/TXT для корня `sonsofgod.ru`, `www` и почты. Перед переключением проверьте `dig uchenik.sonsofgod.ru`, HTTPS, OAuth redirect URLs и почту основного сайта. Без доступа к Beget и выбранному хостингу DNS не настроен.

Для production нужны отдельные настройки секретов на площадке размещения и совпадающие URL в Supabase Auth. Содержимое PostgreSQL остаётся в Supabase независимо от варианта размещения. Проверяйте работу регистрацию → урок → действие → возврат, группу → встречу, права обычного пользователя и администратора **после** подключения реального Supabase и сервера. Наличие успешной локальной сборки не означает production-готовность.

## Безопасность и данные

RLS включена на таблицах личных и групповых данных. Приглашение в группу принимается по уникальному токену с проверкой email текущего вошедшего пользователя; ID группы сам по себе права вступления не даёт. Подтверждённая связь двух зарегистрированных людей создаётся после принятия приглашения; личная запись контакта не считается такой связью. Поколения считаются из подтверждённых связей, без публичных рейтингов.

Запрос на удаление аккаунта требует отдельной защищённой серверной процедуры удаления пользователя из Supabase Auth. Каскады схемы удаляют связанные записи после удаления `auth.users`; до реализации серверной процедуры в интерфейсе нельзя обещать самостоятельное полное удаление аккаунта. Для обработки запроса администратор проекта может удалить пользователя через Supabase Auth при проверке личности и резервного копирования.
